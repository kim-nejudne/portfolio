## Concept

A union type lists alternatives. A value of type `string | number` is a `string` or a `number`, and the compiler accepts either wherever that type is expected. A literal type is a type with exactly one value, such as `'dark'`, `42` or `true`; you met them in <Lesson id="m01-types/02-primitives-literals-widening" />. In a union they become useful: `'light' | 'dark'` is a string type with only two values.

```ts run
type Theme = 'light' | 'dark';

function themeClass(theme: Theme): string {
  return `theme-${theme}`;
}

let userId: string | number = 'u-17';
userId = 17;

console.log(themeClass('dark'), userId);
```

`type Theme = …` gives the union a name. The name is only an alias: `Theme` and `'light' | 'dark'` are the same type. Anything outside the union is rejected where it is written:

```ts run errors
type Theme = 'light' | 'dark';

function themeClass(theme: Theme): string {
  return `theme-${theme}`;
}

themeClass('blue');

let userId: string | number = 'u-17';
userId = true;
```

The union exists only for the compiler. At run time `theme` is an ordinary string and nothing checks it; the protection is that every call was checked before the code ran.

## Examples

Unions also come out of inference. A `const` keeps both literals; a `let` widens each of them to `string`, exactly as it widens a single literal:

```ts twoslash
const coin = Math.random() < 0.5 ? 'heads' : 'tails';
//       ^?
let face = Math.random() < 0.5 ? 'heads' : 'tails';
//     ^?
```

A function can take and return a union of literals. `nextTheme` returns one of two literals, and both are `Theme`s, so the return type checks. `badge` calls a string method: every member of `Theme` is a string, so every string method is available. What comes back is a plain `string`; the compiler doesn't work out that `'light'` becomes `'LIGHT'`.

```ts run
type Theme = 'light' | 'dark';

function nextTheme(theme: Theme): Theme {
  return theme === 'light' ? 'dark' : 'light';
}

function badge(theme: Theme): string {
  return theme.toUpperCase();
}

let current: Theme = 'light';
current = nextTheme(current);
console.log(current, badge(current));
```

A literal union also catches typos: `theme === 'drak'` is an error, _This comparison appears to be unintentional because the types 'Theme' and '"drak"' have no overlap._

`string | number` is harder, because its members share only a few methods. `toString` is one of them, and it returns a `string` for both, so after it every string method is available:

```ts run
type Id = string | number;

function formatId(id: Id): string {
  return `#${id.toString().padStart(4, '0')}`;
}

console.log(formatId(7));
console.log(formatId('42'));
```

A union keeps each member once, and a literal type written next to its own primitive disappears into it. `boolean` is itself the union `true | false`, and every string literal is already part of `string`:

```ts twoslash
type Flag = true | false;
//      ^?
type Size = 'small' | 'large' | string;
//      ^?
```

`Size` is a common mistake when someone means "these sizes, or any other string". The sizes vanish: the editor stops suggesting them, and any string passes.

<Callout kind="tip">
  In the REPL, put the cursor on a type name and press <Key>K</Key>: quick info
  shows what the union became, not what you wrote.
</Callout>

## Pitfalls

**Calling a method only one member has.** On a union you can use only what every member supports. `toUpperCase` exists on `string` but not on `number`, and the error names the member that lacks it:

```ts run errors
function shout(message: string | number): string {
  return message.toUpperCase();
}
```

To use a string method, first find out which member you hold: inside `if (typeof message === 'string') { … }` the compiler treats `message` as a `string`. That check is narrowing, the subject of <Lesson id="m03-unions/03-narrowing" />. Until then, convert to one type first: `String(message).toUpperCase()` compiles for both members.

**Treating a union as one of its members.** Each member fits into the union, but the union does not fit into a member. `parsePort` may return a string, so its result can't go where only a `number` is allowed, even for an argument that is plainly a port:

```ts run errors
function parsePort(input: string): number | string {
  const value = Number(input);
  return Number.isInteger(value) ? value : `not a port: ${input}`;
}

const port: number = parsePort('8080');
```

The compiler goes by the declared return type, not by the argument. Either handle both members where the result is used, which is narrowing again, or give the function a single return type.

**`|` binds more loosely than `[]`.** `string | number[]` is a string, or an array of numbers. For an array whose elements may be either, put the union in parentheses: `(string | number)[]`. The error shows that type, inferred from the array literal:

```ts run errors
const mixed: string | number[] = ['a', 1];
```

And `string[] | number[]` is different again: an array of only strings, or an array of only numbers.
