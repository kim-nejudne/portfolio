## Concept

In <Lesson id="m03-unions/03-narrowing" /> you told the object types in a union apart with `in`, by a property that only one of them has. A discriminated union builds that difference in on purpose. Every member has the same property, the discriminant, and each member gives it a different literal type. Comparing the discriminant with one of those literals narrows the whole object to the member that has it:

```ts twoslash
type Circle = { kind: 'circle'; radius: number };
type Square = { kind: 'square'; side: number };
type Shape = Circle | Square;

function area(shape: Shape): number {
  if (shape.kind === 'circle') {
    shape;
    //  ^?
    return Math.PI * shape.radius ** 2;
  }
  shape;
  //  ^?
  return shape.side ** 2;
}
```

Inside the `if`, `shape` is a `Circle`, so `radius` is there. Below it only `Square` is left, because the `if` returns: the early exit from <Lesson id="m03-unions/04-control-flow-analysis" />. The check is the equality narrowing you already know, applied to a property. And `kind` is an ordinary property that exists at run time, unlike the type names, so the check runs exactly as written.

`'radius' in shape` would narrow here too. A discriminant keeps working when members share property names or make one optional, and it names every alternative in one property that a `switch` can test.

## Examples

**`switch` on the discriminant.** Each `case` narrows `shape` to the member with that literal. When every member has a `case` that returns, the compiler knows the end of the function can't be reached, so no `return` is needed after the `switch`:

```ts run
type Shape =
  { kind: 'circle'; radius: number } | { kind: 'square'; side: number };

function describe(shape: Shape): string {
  switch (shape.kind) {
    case 'circle':
      return `circle with radius ${shape.radius}`;
    case 'square':
      return `square with side ${shape.side}`;
  }
}

console.log(describe({ kind: 'circle', radius: 2 }));
console.log(describe({ kind: 'square', side: 3 }));
```

Take one `case` away and `describe` stops compiling: _Function lacks ending return statement and return type does not include 'undefined'._, the error you met in <Lesson id="m01-types/04-any-unknown-never-void" />. That is a check that every member is handled, but a weak one. It doesn't say which member is missing, and a function that returns nothing, such as one that only logs, gets no error at all.

**Other discriminants.** The discriminant can have any name, `kind` and `type` are common, and any literal type, `true` and `false` included. A result that is either a value or an error is the classic boolean case. `!result.ok` is a truthiness check, and because its branch ends in `continue`, the rest of the loop body sees the other member:

```ts run
type ParseResult = { ok: true; value: number } | { ok: false; error: string };

function parseAge(input: string): ParseResult {
  const value = Number(input);
  if (!Number.isInteger(value) || value < 0) {
    return { ok: false, error: `not an age: ${input}` };
  }
  return { ok: true, value };
}

for (const input of ['41', 'forty']) {
  const result = parseAge(input);
  if (!result.ok) {
    console.log(result.error);
    continue;
  }
  console.log(`next year: ${result.value + 1}`);
}
```

**Exhaustiveness with `never`.** `never` is the type with no values, and <Lesson id="m01-types/04-any-unknown-never-void" /> showed that nothing can be assigned to it. Narrowing can arrive there. Once every member has had its `case`, no member is left for `default`, so `shape` has type `never` there, and assigning it to a `never` variable compiles:

```ts twoslash
type Shape =
  { kind: 'circle'; radius: number } | { kind: 'square'; side: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'square':
      return shape.side ** 2;
    default: {
      shape;
      // ^?
      const unreachable: never = shape;
      throw new Error(`unhandled shape: ${JSON.stringify(unreachable)}`);
    }
  }
}
```

Today nothing reaches that `default`, and the check costs nothing. It pays off later. Add a member to `Shape`, and every `switch` with this check stops compiling, each naming the member it doesn't handle:

```ts run errors
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number }
  | { kind: 'triangle'; base: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'square':
      return shape.side ** 2;
    default: {
      const unreachable: never = shape;
      throw new Error(`unhandled shape: ${JSON.stringify(unreachable)}`);
    }
  }
}

function label(shape: Shape): string {
  switch (shape.kind) {
    case 'circle':
      return `circle, radius ${shape.radius}`;
    case 'square':
      return `square, side ${shape.side}`;
    default: {
      const unreachable: never = shape;
      throw new Error(`unhandled shape: ${JSON.stringify(unreachable)}`);
    }
  }
}
```

`Type '{ kind: "triangle"; base: number; height: number; }' is not assignable to type 'never'.`, once in each function. Read the errors as a to-do list: give each `switch` a `case 'triangle'`, and both compile again.

The `throw` is for values the types don't describe. The result of `JSON.parse` is an `any`, so it can be passed as a `Shape` whatever its `kind` says. Such a value reaches `default` at run time, and an error there beats a wrong answer. Lesson 7.3 turns this check into a function you can reuse, `assertNever`.

<Callout kind="tip">
  In the REPL, after you add a member to a union, <Key>]d</Key> jumps from one
  unhandled `switch` to the next, and the Problems tab in the output pane lists
  them all.
</Callout>

## Pitfalls

**A discriminant typed `string`.** If `kind` is a `string` in every member, `'circle'` could be the kind of either, so the check rules nothing out and nothing narrows:

```ts run errors
type Circle = { kind: string; radius: number };
type Square = { kind: string; side: number };
type Shape = Circle | Square;

function area(shape: Shape): number {
  if (shape.kind === 'circle') {
    return Math.PI * shape.radius ** 2;
  }
  return shape.side ** 2;
}
```

_Property 'radius' does not exist on type 'Shape'._ Each member needs its own literal type for the discriminant.

**An object built before the call.** An object literal written where a `Shape` is expected is checked against the union, and its `kind` keeps the literal type. Built on its own first, it is inferred by itself, and its properties widen, as <Lesson id="m01-types/02-primitives-literals-widening" /> showed:

```ts run errors
type Shape =
  { kind: 'circle'; radius: number } | { kind: 'square'; side: number };

function area(shape: Shape): number {
  return shape.kind === 'circle'
    ? Math.PI * shape.radius ** 2
    : shape.side ** 2;
}

const unit = { kind: 'circle', radius: 1 };
console.log(area(unit));
```

`unit` was inferred as `{ kind: string; radius: number; }`, and the error ends with _Type 'string' is not assignable to type '"circle"'._ Annotate the variable, `const unit: Shape = …`, and the literal is checked against the union where it is written. Passing the object literal straight to `area` works too.

**A `default` that takes real members.** A `default` that returns a value switches the `never` check off: it takes whatever no `case` took, members added later included. `corners` was written when the only other shape was a square:

```ts run
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number }
  | { kind: 'triangle'; base: number; height: number };

function corners(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return 0;
    default:
      return 4;
  }
}

console.log(corners({ kind: 'triangle', base: 3, height: 2 }));
```

It compiles, and prints `4` for a triangle. Give every member its own `case`, and keep `default` for the `never` check.
