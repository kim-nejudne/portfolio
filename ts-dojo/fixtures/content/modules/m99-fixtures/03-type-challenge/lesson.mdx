## Concept

A type can be checked the way a function is tested. `Equal<A, B>` is `true` only when the two types are the same, and `Expect<T>` only accepts `true`, so a tuple of `Expect<Equal<…>>` elements compiles only when every case holds.

```ts twoslash
type Event = { type: 'click'; x: number } | { type: 'keydown'; key: string };

type Click = Extract<Event, { type: 'click' }>;
//   ^?
```

## Examples

Literal discriminants make an object that mixes two members an error, which is what the type cases rely on:

```ts run
type Event = { type: 'click'; x: number } | { type: 'keydown'; key: string };

const events: Event[] = [
  { type: 'click', x: 10 },
  { type: 'keydown', key: 'j' },
];

for (const event of events) {
  console.log(
    event.type === 'click' ? `click at ${event.x}` : `key ${event.key}`,
  );
}
```

## Pitfalls

**A member with the wrong properties.** The discriminant decides which member an object literal is checked against, so `key` is an excess property on a click:

```ts run errors
type Event = { type: 'click'; x: number } | { type: 'keydown'; key: string };

const mixed: Event = { type: 'click', x: 10, key: 'j' };
```
